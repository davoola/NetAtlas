# 网图·IP管家（NetAtlas）

基于 Node.js、Express、SQLite 和 EJS 的 IP 地址管理系统，面向企业园区、学校及多部门网络环境，提供 IP 登记、网段规划、导入导出、统计分析、权限控制和审计追踪能力。

本系统可替代传统 Excel 台账，通过 VLAN 规划与网段映射实现 IP 地址的规范化分配与可用池范围校验，避免 IP 冲突和资源浪费。内置三级角色权限（超级管理员 / 管理员 / 普通用户），支持管理员按 VLAN 授权管理特定网段，满足多部门协同管理需求。所有关键操作均记录审计日志，确保可追溯。

## 技术栈

- **后端**：Node.js + Express
- **数据库**：SQLite（Node.js 内置 `node:sqlite`，单文件、零配置）
- **前端**：EJS 服务端渲染 + 原生 JavaScript（无前端框架依赖）
- **认证**：Session + bcrypt 密码哈希
- **安全**：CSP 内容安全策略、安全响应头、CSV 公式注入防护、服务端权限与输入校验、VLAN 权限默认拒绝
- **接口**：页面路由 + RESTful JSON API

## 主要功能

- **IP 全生命周期管理**：新增、查看、编辑、删除、搜索、筛选、排序和 CSV 导出
- **VLAN 与 IP 子网一致性校验**：IP 必须属于所选 VLAN 的子网，前后端双重校验
- **可用地址池硬校验**：VLAN 规划中配置可用地址范围（如 `.10–.200`）后，新增 / 编辑 / 导入时强制校验主机号落在池内（网关地址自动放行）
- **重复 IP 识别**：重复 IP 红色高亮标注，支持「只看重复 IP」筛选
- **MAC 冲突识别**：相同 MAC 地址在多条记录中出现时高亮，支持「只看 MAC 冲突」筛选
- **网段使用明细**：按网段前缀查看登记记录、已使用 / 可用数量、未登记主机号列表
- **数据字典维护**：设备类型、使用状态、所属部门、VLAN 规划、网关映射、系统配置
- **数据导入**：支持 Excel（`.xlsx`）和 CSV，自动映射常见中文列名，自动填充网关与 VLAN，重复 IP 支持「跳过 / 更新 / 报错」三种策略
- **数据导出**：CSV（UTF-8 BOM），按当前筛选条件导出全部结果，并对潜在公式注入内容进行转义
- **仪表板统计**：KPI 卡片（登记总数、已使用、预留/备用、已废弃、有 MAC、有向日葵 ID、重复 IP、MAC 冲突、使用中 VLAN 等）、VLAN 利用率进度条、部门与设备类型占比
- **三级角色权限**：超级管理员（全部权限）、管理员（仅授权 VLAN 可写）、普通用户（只读）
- **操作审计日志**：记录 IP、字典、用户、导入、系统配置等关键变更，支持按操作人、动作、对象类型、时间范围筛选
- **个人密码修改**：所有用户可验证旧密码后修改自身密码

## 环境要求

- **Node.js 22.5+**（需要支持 `node:sqlite` 与 `--experimental-sqlite`）
- npm

## 快速开始（安装 → 配置 → 初始化 → 启动）

```bash
# 1. 安装依赖
npm install

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env，至少设置：
#   SESSION_SECRET=          # 生产必须；可用: openssl rand -hex 32
#   ADMIN_INITIAL_PASSWORD=  # 可选；8–128 位。不设置则 init-db 时生成随机密码并只打印一次
#   PORT=3000
#   NODE_ENV=production      # 生产环境
#   TRUST_PROXY=1            # 仅在反向代理之后按需开启

# 3. 初始化数据库（创建空字典表 + 初始管理员 admin）
npm run init-db

# 4. 启动
npm start
# 开发模式（文件变动自动重启）：npm run dev
```

访问 <http://localhost:3000>（端口以 `PORT` 为准）。

> `npm start` / `npm run init-db` 会自动读取项目根目录的 `.env`。

### SESSION_SECRET

- **生产环境（`NODE_ENV=production`）必填，且至少 32 个字符**；缺失或过短时服务**直接退出**，不会带病启动。
- 开发环境缺失时会自动生成随机密钥（重启后需重新登录），并打印警告。

### 初始管理员与首次登录

`init-db` 仅在用户表为空时创建超级管理员 `admin`。**系统不存在固定的默认密码，`admin / admin123` 不是有效凭据。** 初始密码有两种方式：

1. **在 `.env` 中设置 `ADMIN_INITIAL_PASSWORD`**（8–128 位，不能是 `admin123` 等已知弱口令），再执行 `npm run init-db`。长度不合规时 `init-db` 会失败并明确报错。初始化完成后建议从 `.env` 中删除该项。
2. **不设置**：`init-db` 生成随机一次性密码，**只在终端显示一次**（请立即记录），并标记该账号**首次登录必须改密**。

**首次登录强制改密**：登录后页面会弹出不可关闭的“修改密码”窗口，改密完成前所有业务接口均返回 403。输入旧密码（即初始密码）和新密码，新密码需满足下方密码规则。

### 密码规则（全站统一，服务端校验）

- 长度 **至少 8 位，最多 128 位**；
- 不能使用 `admin123` 等已知弱口令；
- 适用于：初始化管理员密码、首次强制改密/自行修改密码、超级管理员新增用户时设置的初始密码、超级管理员重置他人密码。

### 从旧版本升级

- 重新执行 `npm install`（依赖有变更）。数据库结构会在启动时自动迁移，无需重建。
- 若仍有账号使用旧版公开默认密码 `admin123`：启动日志会给出警告（生产环境为醒目警告），该账号登录后会被强制改密。请尽快处理。

## 环境变量

| 变量 | 说明 | 默认 |
|------|------|------|
| `SESSION_SECRET` | Session 签名密钥。**生产环境必填且 ≥ 32 字符**，否则拒绝启动 | 开发环境自动随机 |
| `NODE_ENV` | `production` 时 Cookie 启用 `Secure`（需 HTTPS）、启用 HSTS | 空 |
| `PORT` | 监听端口 | `3000` |
| `ADMIN_INITIAL_PASSWORD` | `init-db` 时指定初始管理员密码（8–128 位） | 随机生成并显示一次 |
| `TRUST_PROXY` | 部署在反向代理后时设置代理层数（如 `1`），使真实客户端 IP 与 `Secure` Cookie 判断正确；**未使用代理请勿设置** | 不信任代理 |
| `DB_PATH` | SQLite 数据库文件路径 | `db/ipam.db` |
| `IMPORT_MAX_ROWS` / `IMPORT_MAX_COLS` / `IMPORT_MAX_CELL_CHARS` / `IMPORT_PARSE_TIMEOUT_MS` | 导入文件的行数、列数、单元格长度、解析超时上限 | 20000 / 60 / 2000 / 30000 |
| `EXPORT_MAX_ROWS` | 单次导出行数上限 | 200000 |
| `ACCESS_LOG` | 设为 `0` 关闭结构化访问日志 | 开启 |

完整示例见 [`.env.example`](.env.example)。

## 安全设计概要

- **CSRF**：所有非 GET/HEAD/OPTIONS 请求（含登录、**登出（仅支持 POST）**、导入上传）必须携带服务端 Session 中的 CSRF 令牌（`X-CSRF-Token` 请求头或 `_csrf` 表单字段），否则返回 403。
- **会话**：SQLite 持久化 Session（重启不丢失）；改密、禁用/降权/删除用户、重置密码、修改 VLAN 授权后，相关旧会话立即撤销。
- **权限范围**：统计、VLAN 规划、网关映射、网关查询、导出对受限管理员按其授权 VLAN 过滤；导入的“更新”策略同时校验原记录与新记录所属 VLAN 的管理权限。
- **导入**：文件在独立 worker 线程解析（超时/行数/列数/单元格长度限制），整批写入在一个事务中；可选“严格模式”，有任一行被跳过则整体回滚。审计日志记录批次 ID、操作者、文件名、文件 SHA-256、行数与结果摘要。
- **错误信息**：对外只返回通用/业务提示和请求 ID（`X-Request-Id`），详细错误仅写服务端日志。
- **测试**：`npm test` 使用临时数据库运行安全与权限集成测试（CSRF、VLAN 权限、导入、密码策略、生产启动检查等）。

| 功能                     | 超级管理员 | 管理员           | 普通用户 |
|--------------------------|:----------:|:----------------:|:--------:|
| 仪表板                   | 读写       | 只读             | 只读     |
| IP 登记台账              | 全部 VLAN  | 仅授权 VLAN 可写 | 只读     |
| 网段明细、查询、排序     | ✅         | ✅               | ✅       |
| 数据字典                 | 读写       | 只读             | 只读     |
| 用户管理                 | ✅         | ❌               | ❌       |
| 审计日志                 | ✅         | ❌               | ❌       |
| 系统配置                 | ✅         | ❌               | ❌       |
| 数据导入                 | ✅         | ✅（授权 VLAN）  | ❌       |
| CSV 导出                 | ✅         | ✅               | ✅       |
| 修改自身密码             | ✅         | ✅               | ✅       |

**权限模型说明（并非漏洞，请勿误解）**：

- **超级管理员**：全部权限。
- **管理员**：可**查看**全部 VLAN 的台账，但仅对「用户管理 → VLAN 权限」中授权的 VLAN 拥有**写权限**（新增、编辑、删除、导入）。其仪表板统计、VLAN 规划、网关映射与导出只包含其授权范围内的数据。
- **普通用户（viewer）**：**全局只读**——可查看全部 VLAN 的数据，不能新增、编辑、删除或导入。这是当前产品设计；如需按 VLAN 限制普通用户的读取范围，属于产品需求变更，需另行设计。

## 使用说明摘要

### IP 登记

新增或编辑记录时，系统会校验：

- IP 地址格式
- IP 是否属于所选 VLAN 的子网
- IP 是否位于 VLAN 配置的可用地址范围（网关地址自动放行）
- 字典字段是否有效
- 当前用户是否有对应 VLAN 权限
- 是否存在重复 IP（提示但不强制阻断）

输入 IP 后可根据前缀自动匹配网关和 VLAN。管理员只能操作已授权 VLAN，普通用户只能查看和导出。

记录支持字段包括：IP 地址、MAC 地址、设备名称、设备类型、部门、使用人、位置、使用状态、VLAN、网关、上层交换机、交换机端口、向日葵 ID、登记日期、备注等。

### VLAN 与网段

VLAN 规划可配置 VLAN 编号、名称、网段（CIDR）、掩码、网关、描述和可用地址范围说明（如 `.10–.200`）。系统据此计算容量、利用率和剩余主机号；网关地址不计入可用数。

### 导入与导出

- 导入支持 Excel 和 CSV，系统可识别常见中文列名，并自动填充网关、VLAN 和默认状态。
- 重复 IP 可选择「跳过」「更新」或「报错」。
- 导入前会执行权限、字典值、IP/VLAN 一致性和地址池校验。
- 导出的 CSV 使用 UTF-8 BOM，并对潜在公式注入内容进行转义。
- 建议导入前备份数据库，尤其是选择「更新」策略时。

### 审计日志

超级管理员可按操作人、动作、对象类型和时间范围筛选日志。日志记录 IP、字典、用户、导入和系统配置等关键变更，业务界面不提供删除操作。

## 部署

直接运行见上文“快速开始”。使用 PM2：

```bash
npm install -g pm2
pm2 start index.js --name netatlas --node-args="--experimental-sqlite"
pm2 save
pm2 startup
```

> 使用 SQLite 与同步数据库 API，请保持**单进程**运行（不要使用 PM2 cluster 多实例）。

## 生产环境建议

- 通过 **HTTPS** 暴露服务（反向代理终止 TLS），并设置 `NODE_ENV=production` 与 `TRUST_PROXY=<代理层数>`。
- `SESSION_SECRET` 使用 `openssl rand -hex 32` 生成并妥善保管；**不要提交 `.env`**。
- 限制 `.env`、`db/ipam.db`（含 `-wal`、`-shm`）及备份文件的文件系统权限（如仅运行用户可读写）。
- **定期备份 `db/ipam.db`**（建议使用 SQLite 在线备份或先执行系统内“Checkpoint”），备份文件加密存放，并定期演练恢复。
- 初始化完成后，从 `.env` 中移除 `ADMIN_INITIAL_PASSWORD`。
- 仅授予管理员完成工作所需的 VLAN 权限；定期审查用户、VLAN 授权和审计日志。
- 导入不可信文件前先确认来源；变更 VLAN 规划、网关映射前先确认对现有记录的影响。
- 配置进程守护、自动重启、日志轮转、磁盘告警，并定期执行 `npm audit`。
